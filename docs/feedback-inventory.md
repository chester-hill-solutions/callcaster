# Feedback surface inventory

Source reviewed: CallCaster `dev@6cb6d50f`, 2026-10-03. This is a source audit for #2058 and the feedback outcome #2300. It does not establish deployed or browser layout acceptance.

The user clarified that no alert may move page content when it renders. The [design-system rule](design-system.md#feedback-surfaces) governs the verdicts below. **Keep** preserves the meaning or field association; it does not approve a conditional row that changes page geometry. **Change** changes presentation, not validation, permissions or recovery actions.

## Method and coverage

- Enumerated 1,264 TypeScript/TSX files under `app/` at this source snapshot, then parsed client-capable modules after excluding server-only files. Recorded JSX error expressions, error props, Alert/QueryParamBanner/ErrorBanner uses and native/toast calls.
- Reviewed all 76 error-expression/prop candidates (56 leaf expressions, 20 props) below. Props that only forward an error to another component are identified as adapters, not extra rendered errors.
- Reviewed all 79 Alert uses, three ErrorBanner call sites, the query-banner owner and its one call site, and the native alert/confirm calls. The first keyword scan of 67 files was an initial candidate scan, not the complete inventory.
- Checked the wider 372-line search for error/invalid/failed text, status-driven output, ARIA alerts, and red/destructive styles. The supplemental table covers rendered failures that do not name an error variable; metric colors, destructive action buttons and non-rendered logs are excluded.
- Read the feedback owners and parent hooks before marking a duplicate. An error toast for a mutation and a stored failure reason in a record are different events.
